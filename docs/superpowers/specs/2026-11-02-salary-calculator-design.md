# 秋招薪资计算器网页版设计

日期：2026-11-02。状态：用户已确认设计，进入实现；本文不代表产品已经实现。除明确列为用户决定的事项外，其余均为本设计提出的默认方案。

## 1. 目标与已确认决定

为中国大陆居民个人、普通企业职工提供 offer 到手测算。用户输入月薪和薪资月数，选择城市及适用福利方案，得到逐月现金、全年现金及公积金缴存明细。

用户已明确选择网页版，并要求默认在 localhost 启动。默认开发地址为 `http://localhost:5173`，执行 `npm run dev` 启动；绑定 localhost，固定端口，端口占用时明确报错，不自动改地址。实现完成时启动服务并验证页面可访问。

用户要求公积金比例不填时自动采用所选城市、测算时段的政策参数。对于政策只规定范围的情况，本设计采用政策最低正常缴存比例作测算默认值，明确标记为产品默认假设，不推定为企业实际比例；有唯一规定比例时直接采用规定值。

政策依据与访问限制见 [政策调研](../../research/2026-11-02-china-salary-policy-research.md)。本设计将已核实政策、用户自定义参数和未来预测分开展示。

## 3. 首版范围

包含：

- 可搜索城市栏：北京、上海、深圳、杭州，加自定义地区。四城是首批政策维护范围，不暗示已覆盖全国。
- 支持 2026、2027 两个测算年度，未来未公布时段显示预测标识及沿用的参数来源。
- 完整自然年与入职当年两种模式；单一雇主，工资薪金，无其他综合所得。
- 月薪、年薪月数、额外薪资发放安排、奖金实际预扣方式及符合条件时的年度计税方式对比。
- 基本社保、住房公积金、企业年金、补充公积金、补充保险的适用配置。
- 逐月到账趋势、详细账单、年度汇总、年度汇算估计及政策来源。
- 清空/恢复示例、导出逐月 CSV、浏览器本地保存输入与一键删除。

本期不做：多份 offer 同屏比较、OCR 导入、股票期权、复杂多雇主/实习劳务税计算、境外/非居民、企业完整人工成本核算、公积金贷款或提取资格判断、自动申报和自动抓取政策。已存在前雇主或实习应税收入的用户不显示为准确年度汇算结果，而提示本期不支持合并该类收入。

## 4. 默认示例与输入

初次打开：北京、2026 年、完整年度、40000 元月薪、16 薪；额外 4 薪暂按 12 月一笔全年一次性奖金发放，明确标注这是示例发放假设；基本公积金比例为“自动（按城市政策）”，比例范围情形采用最低正常缴存比例（北京已核实的 2026 公积金年度，个人和单位均为 5%）；不启用额外保险/年金；专项附加扣除默认零。明确示例不代表某家公司真实薪资方案。

月薪支持元和 `40k`，输入归一化后精确到分；月薪范围 0—10000000 元，薪资月数范围 12—36，最多两位小数。月份为整数 1—12。所有金额禁止负数、NaN、Infinity。用户正在输入空值时显示待输入状态，不闪回默认值；非法参数不继续显示旧的有效结果。

普通页面显示：城市、年份、测算模式、月薪、年薪月数、基本公积金比例及奖金计税方式。薪资月数是报价单位，不是银行转账次数；16 薪默认拆成 12 个月工资加 4 个月额外薪资。

公积金比例无需必填，默认显示“自动 · 按城市政策最低比例测算”，同时展示本次个人/单位实际采用值、政策范围及来源。用户知道企业比例时可切换为手动填写，个人与单位比例分别记录。仅此可选比例字段清空时恢复自动；其他必填金额字段清空仍按待输入状态处理。支持一键恢复政策默认。

高级设置分三组：

1. 发放安排：一次奖金、季度绩效、自定义额外收入事件。事件记录金额、发放年月和收入类型。额外收入事件之和必须等于月薪乘以额外薪资月数；有手工调整时显示与报价的差额并要求以日历为准。一个纳税年度最多一笔事件可选择符合条件的全年一次性奖金单独计税；季度绩效归工资。单独计税资格由用户根据实际情况确认，不由计算器把普通奖金改名取得。
2. 企业缴费：社保及公积金基数来源（按月薪估算、上年度月均、自定义申报基数），比例、适用医疗档次、企业年金、补充公积金、补充保险。
3. 个税扣除：住房租金资格及适用月份、其他符合规定的月度专项附加扣除金额、仅用于年度汇算的额外扣除金额。其他金额由用户自行确认资格，提供官方说明链接；住房租金与住房贷款利息不得重复配置。无需身份证、住址或保单号。

## 5. 入职当年模式

选择入职月份、是否新参加工作，以及是否满足该年度首次取得工资的预扣条件。满足首次工资条件时，自年初累计基本减除费用；普通新入职则按本单位任职月数累计。不能仅因勾选应届生而自动认定满足税收条件。

首版按每个在职月发放全月工资，不处理月中入职天数。该限制在模式说明中显示。试用期可配置持续月份和月薪比例，默认无折扣；该比例影响对应月份实际工资。

额外薪资可选择“不折算”或“按当年在职月数/12 折算”，默认后者；明确这是公司奖金规则假设。额外薪资基数用合同月薪，不跟随试用期折扣；可手工改事件金额并显示报价差额。

新参加工作人员公积金默认按政策从第二个月起计缴；新调入/其他情形允许选择首个缴存月份。社保从入职月份按适用规则估算。首版不还原补缴、迟发工资或地方政策追溯征收的实际银行扣款时间；显示按政策应缴的月度估计。

发放日在下一年的奖金，不计入本年度到账与税额，另列“次年计划发放”及金额；首版不跨年度滚动计算次年完整税单。2028 年奖金不推定享受现有单独计税优惠。

## 6. 城市政策与缴费配置

每个险种、基金独立记录：地区、适用身份、有效起止日、公布日、核验日、来源链接、个人比例、单位比例（如需要）、工资口径、基数上下限、固定附加金额、取整规则及官方缴存额限额。国家税率和地方参数分别维护。

政策核实是实现步骤的一部分：发布为可用预设前，须补齐北京、上海、深圳、杭州在所支持时段的个人现金扣费、公积金和税前扣除必需字段，引用主管部门来源。不得以另一个城市数据补缺。费率及封顶有阶段调整的按月匹配。

2027 尚未发布的地方参数可以显式沿用最后核实的数据预测，逐月和汇总均带预测提示；已知到期的税收优惠不得自动延长。2026 历史时段若无法核实，缺项列出，用户补齐后才计算；没有完整数据的地区不显示“官方参数已核实”。

自定义地区必须填写个人养老、医疗、失业的基数、比例、必要固定附加额，以及公积金个人/单位基数、比例和税前扣除上限。全部为用户自填数据，不能据此推定官方认可。该模式允许直接输入个人每月实际缴费金额，便于用真实工资单反推；缴费与允许税前扣除的金额仍独立。

标准企业模式下基本五险为适用身份对应的固定保障项，工伤和生育的个人扣款为零。允许用户开启/关闭企业提供的补充福利，不把法定社保做成可随意取消的服务。深圳医疗档次注明适用条件，用户按实际方案选择。

社保按每项工资口径与上下限计算；不能把年薪月数当作社保月数。新入职默认基数按合同月薪估计，页面标明；既有职工可填写上年度月平均工资。奖金是否进入未来工资基数，本期不自动预测。

住房公积金分别计算个人和单位缴存，上海补充公积金独立配置；实际缴存限额、取整规则和个税允许扣除上限分别维护。个人缴存从现金工资扣除；单位缴存不从个人现金中扣。个人实缴超出允许扣除的部分不抵税；单位超标形成的应税收入另加到计税收入，不能重复加回个人实缴部分。

基本公积金自动比例按城市、身份及月份的有效政策解析：唯一规定值直接采用；仅有范围时分别采用个人与单位的正常最低比例，标记“测算默认，实际以公司为准”。不把适用于特殊困难企业的获批降比/缓缴方案当成普通用户默认。自动模式随城市、年份及年中政策变动重新解析；手动比例在每个适用月份校验，超出范围时提示处理，不能静默截断。补充公积金仍默认不启用，不能因城市允许而自动加入。未核实政策或自定义地区无法推出唯一参数时，不任意回退为全国统一 5%，须补齐资料或用户参数；未来沿用数据仍带预测标记。政策允许范围与采用的测算默认值分字段存储，避免将产品默认值写成官方强制标准。

企业年金可按基数比例或固定金额填写个人与单位缴费；个人税前扣除按适用计税工资基数及 4% 限额校验，个人实际扣款可与其不同。单位超标应税部分另计；单位年金单独展示并提示归属依企业方案，不并入到手。

补充保险输入个人现金扣款、单位承担金额及税务处理。不能确认税务性质的项标成“税务处理待确认”，给出按应税/符合免税或扣除条件两种结果范围；用户确认工资单处理后再给单一结果。税优商业健康险仅在用户确认符合条件时按适用额度扣除，避免默认全部抵税。允许每个福利项分别填写依法可扣除金额，超过实际保费及政策限额时提示错误；符合条件的单位代购保费按政策可视同个人购买，校验实际保费应包含单位承担的相应金额，不能仅以个人工资现金扣款为上限。

只展示测算所需的个人法定社保费及单位公积金/年金；工伤等单位成本不作精确承诺，也不将不完整的单位缴费包装成总人工成本。

## 7. 计算和结果口径

所有账务金额用整数分存储，比例用整数基点或可精确表示的有理数运算。输入小数由字符串解析，避免直接使用浮点数累加金额；每个步骤遵循相应取整规则。单位为元的公积金取整与单位为分的个税计算区分。

计算顺序：发薪事件 → 按月适用政策 → 个人实缴/单位公积金及年金 → 允许扣除和额外应税福利 → 累计工资预扣 → 奖金预扣 → 现金账单 → 年度最终税额及汇算差额。

工资累计预扣按调研文档的年度税率表，当月不产生负预扣退款。年终汇算的基本减除费用按全年 60000 元，年度专项附加扣除按实际符合资格月份及输入确定；与预扣享受时点分开。只有单一雇主、无其他收入的范围内给出年度估计。

实际现金 = 当月发放工资奖金 - 个人实际缴费 - 个人其他现金扣款 - 当月工资及奖金预扣税。年度现金为本自然年 12 行相加。单位应税非现金福利只影响税基，不作为已收到的现金加进工资。

实际奖金预扣方式选择“符合条件时单独计税”或“并入工资”。两种年度最终税负均可比较；较优年度方案不能悄悄替换实际发薪账单。汇算差额定义为最终应纳税额减已预缴额，正数为预计补税，负数为预计退税；不将预计退税加进本年到账。

结果显示：

- 主卡：全年现金到手；次卡：年收入折合每月、全年预扣个税、个人社保公积金。
- 明显区分完整年度/入职当年及“按假设估算/包含预测参数/参数待确认”等状态。
- 每月现金柱状图和可展开明细表；含月、工资、额外薪资、个人社保、公积金、年金/保险、工资税、奖金税、现金到账。
- 点击月份显示计算依据：本月各项基数、个人费率、累计计税收入、累计扣除、适用档位及已预缴税。
- 福利区：个人与单位公积金、年金分别列出。不显示“含公积金到手”这种混淆现金的标签。
- 汇算区：两种奖金方式的最终税负及差额、当前预扣方式、预计退补税金额。
- 对跨年奖金，单列本年未到账金额；报价年薪与实际年内发放额各显示一次，避免暗示首年必然收到完整报价。

政策不完整或输入错误时，显示可操作错误与待补字段，不显示精确单一金额。未知补充保险税务属性可以显示范围，年度和逐月结果都需一致标注范围。

## 8. 页面与交互

页面为中文；桌面输入区在左、结果区在右，移动端上下排列。浅色背景，深色文字，蓝绿色强调，金额使用等宽数字。用留白、清楚的字段标签和层次突出到手结果，避免装饰挤占表单空间。

顶部简短说明计算用途，并展示当前年度和政策核验时间。输入分“薪资方案”“五险两金/补充福利”“高级设置”；按城市仅展示适用项。设置变更后立即重算，输入错误就地显示。切换城市保留工资信息，重置城市相关预设并提示；用户覆盖过的参数需要明确确认重置，不静默带到新城市。

每个输入有可访问标签；开关、折叠、选项卡可键盘操作，表格有表头，图表同时有文字/表格表达，不只靠颜色传达预测与错误。移动端明细可横向滚动，但页面本身不横向溢出。

本地保存采用带 schema 版本的单一 localStorage 项，读取失败或旧版本不兼容时恢复示例，不阻断页面。用户可一键删除；不上传薪资，运行中不请求远程政策接口。CSV 使用 UTF-8 BOM，列明年份、模式、参数状态和金额单位；导出备注使用固定文案，避免将未转义的可控输入当作表格公式。

## 9. 模块边界

- `domain`：输入、政策、月账单、汇算结果类型与金额/校验函数。
- `policies`：全国税率、四城有效时段配置、来源和预测映射；只提供数据，不读取 UI 状态。
- `calculator`：日历、缴费、预扣、奖金和汇算的纯函数；返回结果及用户可读的假设、错误与警示。
- `components`：薪资输入、城市/年份选择、福利配置、结果卡片、月图、账单、依据及来源。
- `storage/export`：浏览器保存与 CSV，不混入税务计算。

文件拆分和组件细节留给实现者；不为未来后台提前搭建 API、数据库或抽象框架。

## 10. 验证与交付

计算逻辑属于核心风险，采用针对性单元测试，而不是为静态文案写重复测试。至少覆盖：

1. 调研中的 40k × 16、每月合规个人扣款 8000 的独立基准：单独计税年现金 464330 元，工资税 49080、奖金税 30590；并入后年税 92280 元、现金 451720 元；两方式差 12610 元。
2. 各级年度税率边界与奖金单独计税边界，包括边界上下 1 分；不提前取整查档。
3. 低收入零税、累计税下降不当月退税、年度汇算退补及现金与权益不混计。
4. 年中首次工资减除费用与普通新入职不同；新参加工作首月公积金为零；试用工资和奖金折算。
5. 各险种独立封顶、医保档次及固定附加、基本/补充公积金取整及扣除限额、年金扣除限额、单位应税非现金福利；公积金未填/清空恢复自动、唯一值与比例范围两种政策、城市/年份/有效月份切换、手动覆盖及越界、补充公积金不自动开启、缺失政策不伪造默认值。
6. 城市/月份匹配、年中基数切换、未来参数带预测状态、缺失政策不能静默计算、跨年奖金排除、每年仅一次单独计税。
7. 逐月现金和税款合计与年汇总一致；计算范围两端一致；CSV 和 localStorage 不改动原始金额。

交付时通过类型检查、计算测试、生产构建；在浏览器验证默认示例、城市切换、入职模式、奖金方式、输入错误、明细/导出及窄屏布局。运行 `npm run dev`，验证 localhost:5173 的真实页面后报告服务地址。
