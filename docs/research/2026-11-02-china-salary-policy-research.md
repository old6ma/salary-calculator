# 中国大陆薪资测算政策调研

调研日期：2026-11-02（北京时间）。用途：为应届生 offer 到手收入计算器提供政策依据和建模输入。本文是调研记录，技术路线、完整城市范围及产品设计尚未确认；未开始产品代码实现。

## 1. 已确认的需求与适用范围

- 面向秋招应届生，解释“40k × 16 薪”这类税前报价。
- 用户输入税前月薪、薪资月数，选择或配置相关保险和公积金项目。
- 提供可选择的城市栏。
- 输出逐月到手和全年到手。
- 当前目录为空，无已有技术栈或业务实现可以沿用。

研究的主要适用对象是中国大陆居民个人、普通企业劳动关系下的工资薪金。非居民、灵活就业、境外所得、股权激励、经营所得和复杂多雇主场景需要独立规则，不能直接套用本模型。

## 2. 结论与证据边界

1. 月薪和薪资月数不足以得到唯一的到手金额，还需要参保地、实际缴费基数、比例、奖金类型和发放时间等。
2. 薪资月数是报价单位，不等于银行转账笔数或社保缴费月数。16 薪可能是 12 个月工资加 4 个月奖金，也可能分散发放，必须显式指定。
3. 个人实际扣款、允许税前扣除金额、单位缴费是三个不同量，应分别建模。
4. 工资累计预扣、年度最终税负和实际收到退补税款的时间，需要分别展示。
5. 六险两金并非统一的计算模板。常见是五险一金加补充医疗和企业年金；不同招聘材料中的第六险也可能是大病保险、意外险等，必须显示实际名称。
6. 全国计算规则可以统一，地方费率、基数、档次、附加费用和取整方法需要按城市及生效区间维护。

本次核实了全国主要税制及北京、上海若干 2026 年地方参数，也核实了深圳医保档次和公积金规则差异；没有完成全国城市政策库。未查到或未核实的城市、年份、险种字段不得标成“官方已核实”。

## 3. 工资薪金个税

依据 [S1]、[S2]：居民个人综合所得按年度计算，基本减除费用每年 60000 元；日常工资按累计预扣法预扣预缴。

### 3.1 年度综合所得税率表

| 全年应纳税所得额（元） | 税率 | 速算扣除数（元） |
| --- | --- | --- |
| 0—36000 | 3% | 0 |
| 超过 36000—144000 | 10% | 2520 |
| 超过 144000—300000 | 20% | 16920 |
| 超过 300000—420000 | 25% | 31920 |
| 超过 420000—660000 | 30% | 52920 |
| 超过 660000—960000 | 35% | 85920 |
| 超过 960000 | 45% | 181920 |

区间上限包含在本档，起征点两侧应有边界校验。应纳税所得额先截断至不小于零，再套税率表。

### 3.2 月度预扣

```text
累计预扣应纳税所得额
  = 累计工资薪金应税收入
  - 累计免税收入
  - 累计基本减除费用
  - 累计允许扣除的个人社保、公积金
  - 累计专项附加扣除
  - 累计其他依法允许扣除

当月预扣税 = max(0, 累计应预扣税 - 此前已预扣税)
```

普通任职情形的累计基本减除费用，按当年在该单位的任职受雇月份数乘以 5000 元确定。计算时保留税额精度，按适用规则在明确的步骤取整到分。

累计计算差额为负时，日常工资预扣阶段不直接形成负税额退款，年度汇算另行处理。

### 3.3 应届生首次取得工资的规则

[S3] 规定：符合条件、在纳税年度内首次取得工资薪金所得的居民个人，扣缴义务人可从年初累计计算每月 5000 元的基本减除费用。例如符合条件的毕业生 7 月首次领薪，当月可累计减除 35000 元。

“应届生”标签不等于自动满足税收条件。入职前是否已有工资薪金、是否按累计预扣法预扣过连续性劳务报酬等，会影响适用资格，且需要向扣缴义务人申明并提供相应资料。学生实习取得劳务报酬还有专门预扣安排。

因此，入职月份、此前收入类型、是否符合首次取得工资条件应是独立输入；不能仅按学历或毕业年份判断。

### 3.4 专项附加扣除

[S4]、[S5]：包括婴幼儿照护、子女教育、继续教育、大病医疗、住房贷款利息、住房租金、赡养老人。优先为应届生解释住房租金、继续教育和符合条件的赡养老人扣除。

- 住房租金按城市条件定额扣除，1500/1100/800 元每月，不是填多少租金就扣多少；还涉及本人及配偶住房、主要工作城市等资格条件。
- 住房贷款利息与住房租金的适用存在互斥约束。
- 2023 年调整后，婴幼儿照护和子女教育各为每名婴幼儿或子女每月 2000 元；赡养老人独生子女每月 3000 元，非独生子女按规则分摊且每人不超过 1500 元。
- 大病医疗在汇算时按规定扣除，不能直接当作每月固定工资扣除。

专项附加扣除减少的是应纳税所得额，不是直接从税款中减去同额金额。实际申报月份和享受月份还可能不同。

## 4. 额外薪资与奖金

[S6]：符合规定的全年一次性奖金，可以选择单独计税或并入当年综合所得；目前明确执行至 2027-12-31。

```text
单独计税奖金适用档位 = 按 奖金总额 / 12 确定
奖金税 = 奖金总额 × 适用税率 - 该档月度速算扣除数
```

| 奖金总额除以 12 后（元） | 税率 | 速算扣除数（元） |
| --- | --- | --- |
| 0—3000 | 3% | 0 |
| 超过 3000—12000 | 10% | 210 |
| 超过 12000—25000 | 20% | 1410 |
| 超过 25000—35000 | 25% | 2660 |
| 超过 35000—55000 | 30% | 4410 |
| 超过 55000—80000 | 35% | 7160 |
| 超过 80000 | 45% | 15160 |

查档时不能把“奖金除以 12”的中间值先粗略四舍五入，从而错误越档；可直接比较奖金总额与月度边界的 12 倍。

[S7]：每人每纳税年度，该单独计税办法只允许采用一次。季度奖、半年奖等其他奖金不能自动逐笔套用。不能为了显示更低税额而任意拆分奖金、改变申报属性或假设公司会改变工资发放。

两种方式都应计算，但“预计全年最终税负较低的方案”和“公司实际预扣方式”应分开。汇算时可能进行的计税方式选择，不等于发薪月已经收到对应退税。

额外奖金如果次年到账，须归入对应实际取得收入的纳税年度；offer 报价所属工作年度与银行入账年度应分别记录。对 2028 年及以后的奖金，在未查明后续有效政策前，不应把目前优惠标为有效。

## 5. 社保、公积金及企业福利

### 5.1 个人与单位分开

依据 [S8]、[S9]，普通企业职工基本养老、基本医疗、失业通常由单位和个人共同缴费；工伤、生育由单位承担，个人不缴费。医疗与生育的合并征缴等地方执行细节仍需按当地规定处理。

| 项目 | 个人现金扣款 | 建模要求 |
| --- | --- | --- |
| 基本养老 | 有 | 个人与单位比例、工资基数与上下限分开存储 |
| 基本医疗 | 有 | 允许档次、固定附加金额和独立基数 |
| 失业 | 有 | 支持地方差异及阶段性政策 |
| 工伤 | 0 | 单位侧展示；行业和浮动费率影响单位成本 |
| 生育 | 0 | 避免和合并征收的医保单位费重复计入 |
| 住房公积金 | 有 | 分别记录个人和单位缴存额，不当作现金到手 |
| 补充医疗/商业保险 | 依企业方案 | 记录具体类型、付款方及税务属性，不能统一认定可全额税前扣除 |
| 企业年金 | 依企业方案 | 实扣金额、允许税前扣除金额、单位缴费及归属条件分开 |
| 补充住房公积金 | 依地方与企业方案 | 独立于企业年金，适用城市单独配置 |
| 地方其他征缴项 | 依有效规定 | 大额医疗、长期护理等逐项核实，避免重复扣费 |

六险两金的真实招聘表述示例见 [S18]。这只是术语示例，不能代替每家企业实际福利方案。

法定参保项目在标准企业测算中应按适用身份和政策处理；用户选择体现适用方案和企业福利配置，不能把所有法定项目表现为可自由取消的消费选项。

### 5.2 缴费基数

每个缴费项应独立确定原始工资口径及上下限：

```text
该项实际基数 = min(max(按该项规则确定的工资基数, 下限), 上限)
该项个人缴费 = 按该项规则取整(实际基数 × 个人比例 + 固定附加金额)
```

不能把当月工资简单乘以“社保总比例”，也不能把 16 薪算成缴纳 16 个月社保。既有职工可能按上年度月均工资确定基数，新入职人员的基数起算规则需要单独维护。奖金是否进入未来基数，应按当地工资口径和实际情形判断，不全国统一推定。

单位申报基数未知时，可以提供“按月薪估算”或“按上年度月均工资估算”，但要公开采用的假设。不能把“按最低基数交”当作任何月薪都合法适用的选项。

### 5.3 公积金的扣款与税务限额

[S9] 对允许扣除的基数和比例有规定，超标准部分涉及计入工资薪金征税。应分别存储公积金缴存规则和税前扣除限额，防止“实缴多少就全部抵税”。补充公积金与基本公积金的扣除额度还需合并校验。

个人公积金从工资中扣除；单位公积金是额外缴存。个人和单位缴存均形成公积金账户权益，现金工资不应计入其未实际提取的金额。

[S10]：新参加工作的职工从参加工作第二个月起缴存；新调入职工的规则不同。城市执行细节与企业实际操作需要结合具体情况。因此入职当年不能机械地假设首月已有公积金。

### 5.4 年金及补充保险

[S11]：符合规定的年金个人缴费，在不超过个人缴费工资计税基数 4% 的标准内，可以暂从当期应纳税所得额中扣除；企业年金计税工资基数另有社平工资 300% 上限规则。这是税务扣除上限，不等于所有企业个人固定扣 4%。

[S12]：企业年金单位缴费每年不超过相关工资总额的 8%，单位和职工合计每年不超过 12%；单位缴费的权益归属还可能随服务年限变化。因此不能把所有单位年金缴费都描述成当期已无条件归属的可支取收入。

[S13]：符合条件的税优商业健康保险有专门的限额和处理规则。普通商业补充医疗、单位承担保费是否形成应税福利、是否满足税优条件，需要按保单和税务规则判断。付款方是公司也不意味着永远不影响员工个税。

## 6. 核实的地方差异样例

下表是说明建模差异的政策样例，不是完整城市配置。

| 地区与时间 | 已核实参数 | 来源 |
| --- | --- | --- |
| 北京，自 2026-07 起社保 | 五险月基数下限 7270 元，上限 36348 元 | S14 |
| 北京，2026-07-01—2027-06-30 公积金年度 | 普通职工基数下限 2540 元，上限 36348 元；比例 5%—12% | S15 |
| 上海，自 2026-07-01 起养老缴费基数 | 下限 7546 元，上限 37731 元 | S16 |
| 上海，2026 年公积金调整 | 基数下限 2740 元，上限 37731 元；基本公积金单位和个人各 5%—7%，补充各 1%—5%，均取整数比例 | S17 |
| 深圳，医保制度 | 一档个人 2%，二档个人 0.5%，不同档次适用范围另有规定 | S19 |

北京社保和公积金最低基数不同，即使同城也不能共用一组上下限。上海公积金公告对双方各 7% 的月缴存额上限写为 5282 元，说明应维护官方缴存额上限与取整口径，而不是只把基数乘比例保留两位小数。

北京 2026 年社保基数公告还涉及追溯到 7 月、后续补收差额的安排。模型应能区分政策生效月份、公告发布日期和实际补缴月份；仅按生效时间分段能算出政策应缴额，但不一定逐分还原实际银行流水。

对于秋招对应的 2027 年入职，尚未公布的新政策时段只能标注为预测。可以沿用最近已核实参数计算估计，但不能把预测写成该年份官方参数，也不能无限延长失效优惠。

## 7. 用于理解结果口径的演算

本例只演示个税和到手口径，不代表任何城市的实际缴费参数。假定 1 月起任职全年、每月税前 40000 元、12 个月工资、12 月额外一次性奖金 160000 元，奖金符合单独计税条件；个人每月社保和公积金现金扣款合计固定 8000 元，全部符合税前扣除规定；没有其他收入、附加扣除、减免、应税非现金福利。

```text
税前年薪 = 40000 × 16 = 640000
工资全年应纳税所得额 = 480000 - 8000 × 12 - 60000 = 324000
工资全年税额 = 324000 × 25% - 31920 = 49080
奖金税额 = 160000 × 20% - 1410 = 30590
全年现金到手 = 640000 - 96000 - 49080 - 30590 = 464330
折合每月 = 464330 / 12 = 38694.17
```

| 月份 | 仅工资预扣税（元） | 仅工资现金到手（元） |
| --- | --- | --- |
| 1 | 810 | 31190 |
| 2 | 2070 | 29930 |
| 3—5，每月 | 2700 | 29300 |
| 6 | 4500 | 27500 |
| 7—11，每月 | 5400 | 26600 |
| 12 | 6600 | 25400 |

12 月加上奖金税后 129410 元，当月总现金为 154810 元。若同一笔奖金改为并入综合所得，年度个税为 92280 元，年度现金为 451720 元；上述假设下，两种方式相差 12610 元。该差额不是所有收入情况下都成立。

演算使用 Python Decimal 复核，并校验逐月税款合计与全年税款、逐月现金加奖金与年度现金一致。没有实现产品计算引擎，也没有用该例证明地方社保配置正确。

## 8. 后续设计需要保留的计算边界

- 输入层同时保留“薪资月数”和实际工资/奖金发放日历，允许小数薪资月数。
- 同时提供完整自然年 offer 比较与入职当年实际现金测算；跨自然年的工作首年需要逐年拆账。
- 输出逐月工资税、奖金税、社保、公积金、其他个人扣款和现金；年度合计按日历汇总。
- 区分年内预扣后现金、年度汇算后净收入和退补税的实际到账时点。
- “含公积金价值”如果提供，应单独展示为现金加个人及单位公积金缴存，不能标成银行卡到手；年金另列并展示归属限制。
- 城市字段表示适用的缴存/参保地区。异地参保等情形需要在高级设置中拆分，而不是仅凭办公地址推定。
- 每条政策至少保存地区、项目、生效起止日、公布日、核验日、官方来源、适用身份、费率、基数、扣除上限和取整规则。
- 配置缺项、年份越界或使用预测参数时，展示具体缺项和假设，不静默套用其他城市。
- 对奖金 36000/144000 等临界点，工资税率边界，跨年重置，7 月变基数，首月公积金，年金扣除限额，未缴社保项、单位福利税务属性和重复缴费进行针对性验证。
